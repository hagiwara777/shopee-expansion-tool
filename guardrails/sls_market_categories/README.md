# SLS Market Category Rules Minimum Beta

Runtime is PH only. `canonical.json` defines the Master Unique Category IDs;
`markets/PH.json` supplies category conditions after Shopee Category confirmation.
No Amazon/Keepa category-name join is permitted. Category ALLOW does not release
Battery, Community NG, own penalty, or any existing product Safety restriction.

PH runtime reads only canonical and PH JSON plus their individual manifests.
No import-time loading, raw CSV dependency, non-PH scan, or fallback is permitted.
Unknown/missing rules stop the affected item at REVIEW; unavailable/corrupt active
assets stop Mapper outputs. Canonical corruption stops the SLS taxonomy service.
Non-PH asset damage does not stop PH runtime, but fails all-asset acceptance tests.

## Reproduction and update

Raw primary CSVs remain external and must not be committed. `source-lock.json`
identifies the five accepted sources by filename, SHA-256, logical CSV record
count and column count. The Master filename has an old date; the adopted source
content is dated 2026-09-17. Identity is determined by the recorded hash.

Run `python scripts/build_sls_category_assets.py --master <path> --requirements
<path> --vn <path> --th <path> --br <path>` with all five explicit external paths.
Add `--check` to compare every generated byte without writing. The source-specific
transform validates all inputs before writing any output; it is not a generic ETL.

1. Independently confirm the new source identity and review source semantics.
2. Update the source lock and version-specific acceptance counts/scopes in a branch.
   Header/meaning changes require transform review; do not silently remap columns.
3. Generate assets, rerun with `--check`, and review normalized/provenance diffs,
   especially NO changes, missing IDs, duplicates, notices, quantity/other conditions.
4. Run all offline tests, protected PH/SG regression and Governance gates; obtain
   acceptance for the new source. Update the source-version count assertion too.
5. Deploy only with **app stop -> code + validated assets -> restart -> new session**.
   Asset hot swap is unsupported. Do not manually edit normalized outputs.

Asset version is SHA-256 of exact UTF-8/LF payload bytes. Manifests are separate to
avoid self-digest cycles. `.gitattributes` preserves those bytes on Windows.
The transform has no timestamps, local paths, API calls or environment inputs.
Each provenance file retains every logical CSV record and raw field including
header/preamble/blank fields. This is lossless at the parsed-field level, not a
promise to reconstruct original quoting/BOM/newline bytes. Exact reproduction
from raw sources requires the external hash-matched originals. Offline tests also
replay logical records to detect hand-edited normalized rules and scope drift.

## Data-only markets and anomalies

SG/MY/TW use Master fields; VN/TH/BR use dedicated sources. Non-PH `action=null`
means runtime NOT IMPLEMENTED, never ALLOW. Raw provenance and basis remain.

- SG: the Pet Food notice binds exactly 100906 through 100915 to Master logical
  record 273 for this source. No forward-fill; revalidate/regenerate on update.
- VN: under/over 1m, whitelist, quantity and remarks stay separate, including YES
  with further-check remarks. The exact 1m boundary remains unresolved.
- TH: ID 102009 has two different category identities at records 293/294; both
  remain in provenance and rule references. Only their equal YES/2 shipping rule
  is indexed once. Do not invent 102010 or other missing categories.
- BR: JPBR and JPBR(Qty limit) are the shipping/quantity authorities. SAGAWA is
  raw provenance only; its YES never overrides JPBR NO.

## Runtime state and rollback

Recommendation holds an independent SLS result bound to market, confirmed ID,
taxonomy, PH asset, transform and evaluator versions. Ready is a pure local AND
with existing Safety/Category/Brand conditions. UI rerun and export load/refresh
against current validated assets; direct export never trusts a saved ALLOW.
Brand confirmation cannot release SLS REVIEW/EXCLUDE. Numeric quantity 1/2 is
REVIEW because stock is not a proven maximum quantity per order.

There is no SLS DB migration or persisted SLS approval. Roll back this scoped
code/asset/test/Governance unit with a normal reviewed revert, then restart and
start a new session. Preserve existing Category/Brand DB and all earlier Safety
assets. No runtime disable/fallback flag bypasses the new checks.
