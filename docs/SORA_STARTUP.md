# Soraの起動と直前の版への復旧

## 通常の起動

新方式を正式版に初めて配置する作業は、Ownerの別承認で行います。配置後は、いつもの「Sora起動.cmd」をダブルクリックします。Python環境・8510・Sora専用の設定ファイル参照は現在のものを使います。商品取得は、画面のボタンを押すまで行いません。

Soraがすでに起動中と確認できた場合は、そのままブラウザで画面を開きます。8510が別のアプリに使われている場合や所有者を確認できない場合は、何も停止せず起動を中止します。旧方式など、起動元を特定できないSoraも安全側で確認不能とします。

空きの場合は最新mainを取得し、正式repository・mainブランチ・未保存変更なし・更新先へのfast-forwardが可能、の条件をすべて確認してから更新します。更新できなければ黒い画面に理由を出し、現在の版で起動します。更新後の状態が確認できない場合は起動しません。Gitが無視しているファイルに衝突する場合も上書きしません。

起動した日時、更新前後のcommit、更新しなかった理由は `%LOCALAPPDATA%\Sora\startup.jsonl` に追記します。記録できない場合は更新しません。記録先を用意できない場合や、ポート・同時起動の状態を確認できない場合は起動も中止します。

この方法は、必須6チェックが成功したPRだけをOwnerがGitHubで確認してmainへ取り込む運用を前提とします。起動時に各PRのCIを再検査するものではありません。Pythonのパッケージは自動更新しないため、必要な環境変更は別途対応が必要です。

## 直前の自動更新前の版へ戻す

手動復旧は通常の自動更新と別の作業です。作業中の画面資料は閉じると消えるため、必要な出力を先に保存し、Soraを終了してください。既存の変更がある場合や手順の途中でエラーが出た場合は、そのまま止めてください。自動復元はしません。

1. `%LOCALAPPDATA%\Sora\startup.jsonl` を開き、最後に「最新mainへ更新しました」と記録された行の `before` のcommitを控えます。
2. PowerShellで下の「正式版フォルダ」を実際のフォルダ名に置き換えて実行し、何も表示されないことを確認します。何か表示された場合は進めません。

   ```powershell
   git -C "正式版フォルダ" status --porcelain=v1 --untracked-files=all
   ```

3. 次の「更新前のcommit」を控えた値に置き換えて実行します。無視対象のファイルにも衝突した場合は止まり、上書きしません。

   ```powershell
   git -C "正式版フォルダ" switch --detach --no-overwrite-ignore 更新前のcommit
   ```

4. 「Sora起動.cmd」で起動します。mainブランチではないため自動更新せず、控えた版を起動します。画面右上の「版」を確認してください。

通常の自動更新へ戻すときは、Soraを終了し、変更がないことを再確認して `git -C "正式版フォルダ" switch --no-overwrite-ignore main` を実行します。次回の起動時に最新mainを確認します。どちらも `reset`・`force`・`stash` は使いません。

## 初回配置のための雛形

`scripts/Sora-Start.cmd.example` は配置後のcmdの雛形です。デスクトップ側はリポジトリ内の `Start-Sora.cmd` を呼ぶだけで、エラー時の画面保持もリポジトリ側で行います。初回配置時に、現在使用しているPython、正式版フォルダ、Sora専用の設定ファイル参照をそれぞれ引き継いで置き換えます。雛形やリポジトリへ実際の認証内容は記載せず、設定ファイルの中身も読みません。正式版フォルダの更新とデスクトップcmdの置き換えは、この文書を作っただけでは実行しません。
