# 出品支援ツール完成定義案（PH v1）

## 文書の状態

これは設計ゲート用の**提案**です。オーナーが事業上の期待と合うことを確認するまで、
完成条件・範囲・優先順位の正式決定ではありません。

## 目的の理解

PHで出品準備をする作業者が、ASIN、Shopee Category ID、Shopee Brand IDを、
根拠を確認しながら取得し、既存出品ツールへ**手作業で**入力できるようにする。

技術方式を選ぶことはオーナーの役割ではない。オーナーが確認するのは、作業時間や
確認漏れが減り、実際の出品準備に役立つ結果になっているかである。

## 推奨するPH v1の範囲

### 使う人と完成時の体験

1. 作業者が英字の商品名を入力し、ASIN候補を取得・確認する。
2. 確認済み候補をPHの出品前保安ゲートで確認する。
3. ELIGIBLE の候補について、作業者がCategoryとBrandを画面で確認する。
4. 確認済みのCategory ID、Brand ID、必須属性の情報、ASIN一覧を出力し、作業者が
   既存出品ツールへ手入力する。
5. 不明、要確認、除外の候補は、出品準備済みとして混ぜず、理由が分かる状態で止める。

各画面・CSVの受け渡しは、作業者が必要に応じて手動で行う。自動実行順序、共有状態、
外部出品ツールへの自動投入は作らない。

### PH v1で完成とみなす条件（推奨案）

次をすべて満たしたとき、PHの出品支援ツール v1 を完成受入の候補とする。

1. **ASIN確認**: 事前に選んだ新規の代表的なPH商品20件で評価し、少なくとも12件は
   正しいASINとして確認できる。確認できない候補は PENDING または REVIEW として
   残し、誤ったASINを確認済みとして出力しない。
2. **安全な候補選別**: PHのGateが各候補を ELIGIBLE、REVIEW、EXCLUDE のいずれかへ
   分け、REVIEW と EXCLUDE がCategory Mapperの出品準備対象へ混ざらない。
3. **Category / Brand確認**: 出品準備対象は、画面に表示された候補または確認済みの
   ローカル情報から作業者がCategoryとBrandを選ぶ。推測したIDだけで出力しない。
   No brand は、候補として確認でき、作業者が明示的に選んだときだけ使う。
4. **出品準備結果**: 条件を満たした候補について、ASIN、Category ID、Brand ID、
   必須属性の情報が分かる一覧を作業者がダウンロードできる。既存出品ツールへは
   作業者が手入力し、外部サービスへは書き込まない。
5. **実業務での受入**: オーナーが、上の結果を使って少なくとも一度のPH出品準備を
   最後まで確認し、「現状より準備作業に役立つ」と受け入れる。

20件中12件は、誤った候補を通さないことを最優先にしつつ、有用性を確認するための
控えめな開始基準である。実データを使う評価の前に、オーナーは「12件で十分か」では
なく、**正しい候補が6割程度でも、残りを安全に保留できれば実務で役立つか**だけを
確認すればよい。役に立たない場合は、数値ではなく期待する作業の姿を伝えればよい。

## 現行実装との照合

| 領域 | 確認できた現行の動作 | PH v1の扱い |
| --- | --- | --- |
| 調査CSV取込 | PH・Japanの調査行を検証し、Resolver向けの小さなTSVを作る。外部APIは呼ばない。 | 利用可能 |
| ASIN Resolver | 商品名から外部AI用プロンプトを作り、候補を確認する仕組みがある。到達性能は未評価。 | 実データ評価が必要 |
| 出品前保安ゲート | SG / PHを選択でき、PHでは市場別辞書で ELIGIBLE / REVIEW / EXCLUDE を出す。 | 利用可能。ただし法令・出品可否の保証ではない |
| Category Mapper | PH限定。PH GateのELIGIBLE CSVだけを出品準備済みにできる。Expansion候補CSVは確認用に読めるが、Gateを通る前には出品準備済みにしない。 | 利用可能。実画面・実業務受入が必要 |
| 既存出品ツール | 貼付用テキストは作れるが、外部ツールの正式入力契約は未確認。 | 手入力のみ。自動連携は対象外 |

## 今回の完成条件に含めないもの

- 既知ASINから派生ASINを取得するExpansion ToolのPH受入
- Keepa、Shopee Catalog API、外部AIの実行
- 実商品データを使う評価
- Shopeeまたは既存出品ツールへの書込み、自動投入、自動出品
- SG / MY / TH対応
- Category Mapper AI Shadow
- 出品後商品改善ツール、Amazon仕入れ支援ツール

Expansion Toolは有料Keepaを使い、画面上のGuardrail表示も現在はSG辞書を示すため、
PH v1の達成根拠には使わない。これは機能の削除ではなく、PHでの完成を未検証の機能で
主張しないための境界である。

## 残課題と推奨順序

1. オーナーがこの提案の「役立つ状態」と範囲を確認する。
2. Resolverの20件評価用に、評価方法と正誤確認の根拠を固定する。
3. PH Gateのテスト用基準辞書と、Gate CSVの再検証方針を整える。
4. 現行実装との差分を監査し、必要な実装・テストを行う。
5. オーナーの明示承認後だけ、少量の実データ、必要な外部API、実画面で受入を行う。

## オーナーに確認すること

次の二点だけ確認する。

1. PH v1の最初の完成を、上記の「商品名からASIN確認、PH Gate、Category / Brand確認、
   手入力準備」までとしてよいか。派生ASIN取得は次の工程に分けることを推奨する。
2. 正しい候補が約6割でも、誤った候補を通さず残りを保留できるなら、最初の実用版として
   役に立つか。役に立たない場合は、必要な作業の姿をオーナーの言葉で示す。

オーナーがここを確認した後にだけ、この提案を正式な完成条件・受入条件として正本化する。
