# PH・SG実務Beta：少量受入計画とOwner判断資料

DEC-0137、[完成条件C01〜C12](PRACTICAL_BETA_COMPLETION.md)の実務受入計画。
既存[SG通常継続利用](SG_CONTINUOUS_OPERATION.md)の「Expansion由来A→Resolver由来B」少量2商品群を維持する。
新しい共通保存・状態操作の受入を追加し、過去Step 8やofflineの成功を新しい実務成功へ読み替えない。

## 実施順と対象

1. P1〜P4のoffline回帰・mock画面操作・移行しない保存試験を完了する。
2. Ownerが対象release、PH／SG shop、保存先、認証利用、API・費用枠、実商品を明示承認する。
3. SGはA=Expansion、B=Resolverから各1〜3商品の準備対象を選ぶ。PHも同じ2入口を各1〜3商品で確認する。
   同一ASINの再登場、同じCategory／Brandの別商品、確認待ちを含むよう選ぶ。
   自動確定対象と対象外、人間確認、重複は保存fixtureで網羅し、実商品で危険品の出品を試さない。
4. 各国でAの確認途中に停止／再起動し、再開→B追加→両群の完成分をまとめて出力する。
5. 最新の実資料と条件に結合した証拠を揃え、Ownerが同じ手順で反復利用できたか確認する。

1〜3商品は準備対象数であり、Expansionの取得数・課金数ではない。
Finderの1ページは最大50候補の現行取得経路を想定し、候補詳細取得分も事前予算へ算入する。
受入商品本文・画像・出品資料はGitへ入れず、承認した市場別保存先で管理する。
テスト用変造資料は複製fixtureとして区別し、実出品資料へ上書きしない。

実出品はこの計画の承認だけでは行わない。
A05の実際の出品済み照合には既存の正当な出品済み商品・最新CSVを使える。
新商品を実出品する必要がある場合は、対象ASIN・shop・操作を別途承認する。
実出品なしのmock遷移と実際の投入／照合を報告で分け、未実施部分をPASSとしない。

## 人間に残す作業

- Amazonの商品同一性・仕入れ時の価格／在庫、判断不能商品の用途・本体／同梱などを確認する。
- Seller Centerの必須属性、カテゴリ適合、発送方法・SLS条件・販売条件を確認する。
- CSV／TXTを外部ツールへ手動投入し、投入結果を明示する。結果不明時には実際の反映を照合する。
- 全ショップの最新出品資料を揃え、出品済み・エラーを確認する。推測で出品済みにしない。
- 価格／評価フィルターを採用した場合、取得時点の概算条件であることを理解し、購入価格保証と扱わない。
