# PH Guardrail Keepa Field Impact Analysis v0.1

**文書状態：レビュー用分析資料／未承認／未正本化**
**運用ルールの正本：`guardrails/prohibited_brands_ph.csv` および `guardrails/risk_keywords_ph.csv`**
**実施範囲：読み取り専用分析。Keepa API、実商品、Shopee書込み、辞書・schema・商品コードの変更は行っていない。**

## 1. 目的と結論

この資料は、現在のPH `BLOCK` 31ルールについて、Keepaの追加情報が既存の一発アウト候補の検出を改善し得るかを整理するためのレビュー資料である。

結論は **HOLD** とする。

- 現在の31ルールは、1件のASIN完全一致と30件の商品名部分一致で判定している。
- 現時点で確認できた既存キャッシュ・fixtureには、親ASIN、EAN、UPC、GTIN、成分、警告等の詳細情報は保存されていない。
- 追加情報が有望なのは、自社ペナルティ品と同一商品の別ASINを、親ASINまたは識別番号で狭く特定する仮説だけである。
- その項目がAmazon.co.jpのKeepa応答で安定して取得できるか、また付属品まで誤って止めないかは未確認である。

よって、Safety Snapshotの契約設計やGate実装には進まない。次に進む場合は、事前承認を得た少数・上限付きのKeepa読み取り確認を別途提案する。

本分析は、未知の危険の網羅的な発見、PHでの出品可否、法令適合、真贋を評価または証明するものではない。これらは本分析の対象外である。

## 2. 確認した事実

- 基準となるremote main: `a364b42d09afd11ba61b556ead675d677652aa70`
- 現行PH辞書: キーワード89件（BLOCK 31、REVIEW 58）、ブランド有効ルール0件。
- `guardrails/prohibited_brands_ph.csv` は必須ヘッダーだけを持つ1行の有効な空辞書である。
- `modules/guardrails.py` は、必須ヘッダーが正しい空辞書を有効として読み込み、PHではブランドルール0件を許容する。
- `tests/test_guardrails.py` は、PHでブランドルール0件・キーワード89件を明示的に検査している。
- 現行Gateへ渡される候補情報は、ASIN、商品名、ブランド、Amazonカテゴリを中心とする。`modules/keepa_client.py` はKeepa応答からこれらとカテゴリ経路を正規化して保存するが、詳細商品応答全体は保存していない。
- Keepa Pythonライブラリのローカル説明では商品応答のキーは商品ごとに変わり得る。候補となる詳細項目のAmazon.co.jpでの取得率は、実APIを使わずには未確認である。
- 現行fixtureにはKeepa詳細項目を含む商品応答の実例がない。

## 3. 分析方法と限界

各BLOCKルールについて、追加情報があれば現在の判定根拠を強くできるか、誤停止やREVIEW増加を招くかを分類した。

- **A — 現行照合で判定可能:** 現在のASINまたは商品名の契約だけで、当該語を含む候補を判定できる。これは検出漏れがないという意味ではない。A分類は、追加Keepa項目がなくても現行ルールを実行できることだけを示す。現行BLOCK条件の妥当性、過剰一致、規約上の正しさを承認するものではない。
- **B — 追加情報が役立つ可能性:** 明確に同一商品と確認できる場合だけ、別ASIN・表記揺れの検出を補助できる可能性がある。
- **C — Keepa情報だけでは判定困難:** 配送可否、付属品か本体か、規制、真贋等の外部・事業判断が残る。

この資料は、既存31ルールの精度改善だけを検討する。新しい危険種別の発見、PH規約の網羅、ブランド／IPリスク全体の評価、Keepa連携全体の投資判断を行うものではない。

## 5. 項目別の採否見通し

| 候補項目 | 現行での保存・利用 | BLOCK改善の仮説 | 現時点の判断 |
| --- | --- | --- | --- |
| ASIN | 利用済み | 自社ペナルティASINの完全一致 | 維持。追加実装不要。 |
| 商品名 | 利用済み | 明示語の検出 | 維持。追加実装不要。 |
| ブランド・カテゴリ | 利用済み | 将来の限定的なREVIEW補助の可能性 | PHブランドルール0件のため、BLOCK強化根拠にはならない。 |
| 親ASIN | 未保存・取得可否未確認 | 同一商品の別ASINを狭く検出 | 小規模確認の候補。単独BLOCKには使わない。 |
| EAN／UPC／GTIN | 未保存・取得可否未確認 | 同一商品の別ASINを正確に特定 | 小規模確認の候補。ただし既知の識別番号台帳も必要。 |
| メーカー・型番・品番 | 未保存・取得可否未確認 | 同一性の補助 | 自動BLOCKでなくREVIEWの補助候補。 |
| Features・Description | 未保存・取得可否未確認 | 商品名にない明示語の補助 | 表現量が多く誤停止の危険が高い。初期採用しない。 |
| 成分・警告・危険物・電池・成人向け | 未保存・取得可否未確認 | 新しい懸念の補助 | 現行31 BLOCKの直接改善根拠が弱い。初期採用しない。 |

## 6. 追加情報を利用する前の安全条件

将来、候補項目を採用する場合にも、次を満たすまでBLOCK範囲を広げない。

1. Amazon.co.jpのKeepa応答で項目名・値・欠損率を少数サンプルで確認する。
2. 自社ペナルティ品について、ASINと追加識別子の対応を一次記録で確認する。
3. 同系列の付属品・ケース等を誤って止めない条件をfixtureで確認する。
4. 項目欠損を自動BLOCKにしない。REVIEWにするかも、実測した業務負荷を見て別途決める。
5. Gate判定、辞書、実務上の限定試行判断を混同しない。

## 7. Phase 0の判定

v0.2企画書の分析目的には到達した。31 BLOCKルールを分類し、追加Keepa項目の有力候補を親ASINと識別番号に限定した。

ただし、採用候補の取得可能性・正確性・誤停止率は未確認である。したがって次の提案は **HOLD** とする。

> Keepa Safety Snapshotの設計や実装には進まない。まず、費用と最大ASIN数を事前提示した小規模・読み取り専用のKeepa確認が必要かを、オーナーが判断する。

この資料自体はGuardrail辞書、Gate、Candidate CSV、Gate結果CSVの正本を変更しない。
