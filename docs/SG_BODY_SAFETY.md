# SG 包丁・コンタクトレンズ本体の確認と除外

販売方針の正本はDEC-0129。レンズ本体・実同梱品は公式根拠による除外、
一般台所用包丁本体・実同梱品は当社の内部暫定除外である。包丁の現行Shopee通常出品条件が確定したとは扱わない。

## 通常の操作

SGの出品前保安ゲートを実行すると、対象商品の本体・実同梱の確認を表示する。
商品名と指定済みProduct Text Safetyの取得済み文章だけで疑義を検出する。
例えばKitchen knife / knives、Chef knife / knives、包丁、Contact lens / lenses、カラコンが対象になる。
カテゴリ、検索起点の情報、AI分類で本体を確定しない。追加APIは呼ばない。

|確認状態|今回追加する処理|
|---|---|
|本体が含まれるか不明|SG_BODY_REVIEWで停止し、商品内容・実同梱を確認する|
|本体または本体を含むセットを確認|SG_BODY_EXCLUDEで除外し、ELIGIBLE CSVへ出さない|
|本体なし・付属品／ケア用品のみを確認|今回の本体疑義だけを解消し、既存Safetyとその他のGate条件を維持する|

本体・付属品の確定には、名称だけで判断しなかったことの明示確認と、確認した資料・同梱内容の根拠が必要。
名称一致や選択欄の変更だけでは通過できない。本体確認済みの除外を同じ確認操作で付属品へ変更できない。
既存Guardrailの判定欄はそのまま残し、追加Safetyの結果は最終判定・理由・判定メモへ記録する。
既存のcontact lens等のREVIEWも、この機能では解除しない。付属品の販売可能性を保証しない。

## 保存・再開・取り違え防止

同じ入力の画面再描画とGate再実行には確認結果を保持する。
統一ベータの[Expansion内部引継ぎ](EXPANSION_GATE_HANDOFF.md)では、入力元・filename変更時も
既存validatorで同じCandidate・商品文章との対応を検証して確認済みEXCLUDEを保持する。
画面を閉じて再開する場合は「SG本体確認記録を保存」でJSONを保存し、同じ候補・商品文章と一緒に読み込む。
記録を読み込まなければ疑義は未確認として停止する。別sessionで過去の本体除外を自動復元するDBは作らない。

記録はSG、対象ASINと商品群、Candidateの全15項目・全行・source type、指定した商品文章Fact、
確認方式versionとDEC-0129へ結び付く。商品文章sidecarを使った場合は元CandidateのSHAもそのFact契約に含まれる。
Candidateの意味上の内容が同じならファイル名の変更は許す。別ASIN、取得日時変更、商品文章変更・削除、
別市場・別version、古い候補の記録は流用できない。不一致・記録不正ではGateの出力を停止する。
同一ASINが重複したCandidateへの本体確認は拒否する。Candidateを整理してから確認する。
hashは対応関係・偶発的編集の検出用であり、確認者の真正性や資料の正確さを証明する電子署名ではない。

SG Category Mapperへ進む付属品対象では、元Candidate・文章・未評価画像の入力資料と一緒に、この確認記録を指定する。
古いELIGIBLE CSVがあっても、未解決疑義や確認済み本体をそのまま準備出力へ通さない。
出力時には現在の商品・商品文章との対応と既存Guardrail / Brand / SLS / 武器画像条件を再確認する。
商品文章が変わった後は古い付属品確認を使わない。CSVとTXTは同じ準備判定を使う。

## 範囲と既知制約

- PHと他市場へ適用しない。既存BLOCK／REVIEW、Battery、SLS、Community NG、武器画像の停止を維持する。
- 固定15列Candidate、既存Gate CSV列、DB schema、Keepa取得・cache、認証、API枠、起動設定を変更しない。
- 新しい疑義の語句は限定的で、表記未検出の商品を安全と保証しない。全商品・全欠損の確認には拡張しない。
- 分類Shadow V3、汎用Review基盤、販売規制マスターへ接続しない。
- コード採用と稼働端末への反映、offline検証と実商品受入は別である。稼働設定・データ・消費記録を自動更新しない。

確認契約・疑義検出を変更する際はversionを更新し、古い記録を自動適用しない。
通常revertで今回のコード・画面接続を戻せるが、DEC-0129の販売除外方針は別途判断なしに撤回しない。
保存済み確認記録や本番データを削除しない。
